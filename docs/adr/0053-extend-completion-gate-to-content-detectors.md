# ADR-0053: Extend the pre-completion gate to the reliable content-quality detector classes

- **Status:** Accepted
- **Date:** 2026-08-01

## Context

ADR-0051 ("Shift-left generation integrity") named a four-layer plan to stop targeting perfect generation and instead guarantee that no *mechanically-detectable* defect is ever delivered. Layer 1 (structural DB constraints) and the ADR-0049 structural gate were already shipped earlier the same day. This ADR is layer 2: **extend the pre-completion gate to the content-quality detector classes**, not just the structural ones ADR-0049 covered.

ADR-0049 built exactly one chokepoint — `public.package_completion_blocking_defects(_pkg mystery_packages)` — called from three places that can each independently mark a package `completed`: the `validate_package_characters()` trigger (fires on the `generation_completed_at` NULL→NOT NULL transition), and the two recovery crons `heal_completed_packages()` and `promote_complete_packages()` (which ADR-0049 found both **bypass the trigger by construction** and would silently re-promote a blocked package within the next 2-minute tick if not also gated). ADR-0049 scoped the function's checks deliberately narrow — `invalid_role` and `error_body` only — because its other candidate checks (`multiple_murderers`, `name_background_mismatch`, `duplicated_cast`) require human judgment to resolve, and a blocking gate that gets those wrong false-blocks real, paying customers.

Separately, ADR-0042 (2026-07-25) and ADR-0041 (2026-07-22) built five read-only `list_packages_with_*()` detectors for content-quality defects that reached customers as `completed` with every field populated: meta-text/chain-of-thought leak, evidence-card culprit spoiler, victim mismatch, slip-culprit leak, self-directed questions, and (ADR-0041) cross-character identity contamination. Four of the five were validated against full history with **zero false positives** and wired into the 6-hourly health check; the fifth (evidence-culprit spoiler) was found to have a high false-positive rate and deliberately left advisory-only.

ADR-0051's read of this: unlike ADR-0049's structural checks, the content-quality classes are *also* mechanically detectable — the ADR-0042/0041 validation work already did the hard part (proving low/zero false-positive rate against full history). The same "detect == gate" reuse ADR-0049 established for structural defects applies here. This ADR does that extension.

## Decision

Extend `package_completion_blocking_defects()` in place — the same single shared function ADR-0049 built — to also check the four reliable ADR-0042 classes plus the ADR-0041 identity-conflict class:

- `meta_text_leak` — model chain-of-thought / template-artifact markers (package- and character-level fields)
- `self_directed_question` — a character's "questions to ask" list targeting themselves
- `victim_mismatch` — `game_overview`'s named victim absent from `master_context` and every character background (a foreign-victim bleed)
- `slip_culprit_leak` — a random-slip ("character" style) game's static secret is a fixed murder confession
- `identity_conflict` — ≥2 characters' scripts claim the same kinship term their own background/relationships never establish

Because all three enforcement paths already call this one function and only branch on `IS NULL` / `IS NOT NULL`, **no trigger or cron function needed to change** — the entire migration is one `CREATE OR REPLACE FUNCTION` on `package_completion_blocking_defects()`. This is the same chokepoint-reuse property ADR-0049 established, now paying off a second time.

Each check is a **per-package predicate** (`WHERE package_id = the row being checked`), not the full-history `list_packages_with_*()` scan — the gate runs inside a per-row completion trigger and cannot afford a table scan per completion. Regex markers, thresholds, and heuristics are ported **verbatim** from the validated read-only detectors (e.g. the tightened meta-leak marker set from the 2026-07-25 validation pass; identity-conflict's `>=2` claimant threshold from the 2026-07-22 validation). Only the query shape changes.

### Two exclusions, deliberate

1. **`evidence_culprit_spoiler` — EXCLUDED.** ADR-0042 validation found a high false-positive rate (the murderer's surname legitimately appearing as a location, family name, or common word; host sections using `### IMPLICATIONS` instead of `#### SIGNIFICANCE` so stripping misses them). It was already excluded from health-check alerting for the same reason. Gating completion on a noisy detector would false-block real, paying customers' legitimate packages — a strictly worse failure mode than the rare spoiler it might catch. Confirmed: stays advisory-only, same as today.

2. **`missing_evidence_images` — EXCLUDED.** Evidence images are generated asynchronously, in a separate, later step (Make → Replicate) than the text content this gate otherwise checks. Gating completion on their presence risks a **race against normal, successful generation**: a package whose text is entirely clean would sit in `needs_review` for however long image generation takes, indistinguishable from a genuinely broken package. The ADR-0016 detector already tracks this as a decoupled, non-blocking backlog specifically *because* blocking the whole product over a missing illustration was already judged the wrong UX call once (see ADR-0016's own reasoning) — and the ADR-0047 auto-remediation worker now actively self-heals this class (recalls `generate-evidence-images` for missing rounds) as a post-completion backstop. Blocking here would convert a self-healing async gap into a manufactured `needs_review` event on every normal package whose images simply haven't landed yet. Left to the worker, as today.

### Interim behaviour until layer 3 (child-content regenerator)

A package blocked on one of the five new classes becomes `needs_review` and **HOLDS** — no auto-repair exists yet for most of these classes at the gate's point of action. Two carve-outs already self-heal in practice: `self_directed_question` is fixed post-completion by the live ADR-0047 worker (deterministic retarget, no judgment required), and `missing_evidence_images` is excluded from the gate entirely (per above) and self-heals via the same worker. So in practice, only `meta_text_leak`, `victim_mismatch`, `slip_culprit_leak`, and `identity_conflict` packages sit in `needs_review` awaiting human repair or ADR-0051 layer 3 (the child-content regenerator, which would let the gate's "hold" become "self-heal" for these too). This is the intended interim trade-off named in ADR-0051: hold rather than ship a detectable defect.

## Rationale

- **Reuses validated detection logic, not new heuristics.** Every regex and threshold in this migration already survived ADR-0042/0041's history-wide false-positive validation. This migration's own risk surface is limited to the query-shape port (history scan → per-package predicate), which the disposable-row verification (below) exercises directly.
- **One function, three enforcement paths, zero new surface.** Extending `package_completion_blocking_defects()` in place means the trigger and both recovery crons pick up the new checks for free, with no risk of the three drifting out of sync — exactly the property ADR-0049 built this function to have.
- **Excluding the two noisy/racy classes is the same discipline ADR-0049 already applied to its own structural checks** (leaving `multiple_murderers`/`name_background_mismatch`/`duplicated_cast` out because they need judgment). A prevention gate's false positives block real revenue; a detector's false positives are merely annoying. The bar for "block on this" is higher than the bar for "alert on this," and both exclusions fail that higher bar for reasons specific to each (noise vs. a structural async race).

## Alternatives Considered

1. **Gate on all six ADR-0042/0041 classes, including `evidence_culprit_spoiler`.** Rejected — see Decision. The same false-positive rate that kept it out of health-check alerting makes it worse, not better, as a blocking gate.
2. **Gate on `missing_evidence_images` too, accepting the async-race latency.** Considered, since "block completion until images exist" is a plausible reading of "no detectable defect delivered." Rejected because the race is structural (image generation is a separate, slower, later pipeline step by design), not a bug to work around, and the ADR-0047 worker already gives images the same "detect, don't ship broken, self-heal" property this whole ADR-0051 program is going for — just via a different, already-shipped mechanism instead of the completion gate. Gating here would regress UX (every normal package waits on images before the host sees anything) for no additional safety the worker doesn't already provide.
3. **Call the existing `list_packages_with_*()` functions directly from inside the trigger**, instead of porting per-package predicates. Rejected per the task brief and on inspection: those functions scan `mystery_packages` history-wide (`generation_status = 'completed' AND created_at >= _since`); invoking one per completing row would turn every package completion into an accidental full-table scan. The per-package predicate achieves identical matching semantics at `O(1)` (relative to history size) cost.
4. **A separate function/trigger for content checks, parallel to `package_completion_blocking_defects()`.** Rejected for the same reason ADR-0049 rejected a second structural trigger: two independent gates reacting to overlapping conditions on the same completion moment is harder to reason about, and risks exactly the recovery-path-bypass bug ADR-0049 had to fix once already if the second gate isn't also mirrored into both crons.

## Verification

Run live against the production DB (`mhfikaomkmqcndqfohbp`), using disposable rows created and deleted within the same session — nothing left behind:

1. **Each of the five new classes individually confirmed to fire**, via direct calls to `package_completion_blocking_defects()` against purpose-built single-package fixtures: a bracketed `[CLOSING PARAGRAPH ...]` authoring note in a character script (`meta_text_leak.character.*`); a chain-of-thought phrase in `game_overview` (`meta_text_leak.package`); a `**To <own name>:**` question (`self_directed_question.*`); a `game_overview` naming a victim absent from `master_context`/backgrounds (`victim_mismatch.*`); a character-style package with a static secret pairing a confession phrase with a guilt-concealment phrase and no `murderer` role (`slip_culprit_leak.*`); and two characters both claiming an unestablished "brother" relationship (`identity_conflict.brother:...`).
2. **A bug caught by this same verification pass, fixed before anything went live:** the `meta_text_leak.package` check originally wrote `_defects := _defects || 'meta_text_leak.package';` — an untyped string literal against a `text[]`, which Postgres resolves to the `array || array` operator (attempting to parse the literal as an array literal) instead of array-append, raising `22P02: malformed array literal` on the very first package that tripped it. Fixed with an explicit `::text` cast, matching how every other append in the function is already unambiguously typed (the result of a `||` concatenation, never a bare literal). Re-verified clean afterward. Recorded here because it's exactly the kind of thing this verification step exists to catch — no live traffic was ever exposed to it.
3. **Clean package — no false positives**, including a direct regression check of the original ADR-0049 "iron gateway" false-positive concern plus new content-specific traps: a character legitimately named with "Twin" in it, a legitimately-established "my brother" relationship (present in the character's own background, so correctly under the ≥2-*unestablished*-claimants threshold), and a self-directed-looking question that actually targets a *different* character. All returned `NULL`.
4. **Structural regression check** — an `invalid_role` + `error_body` fixture (mirroring the original Coronation shape) still correctly returns both `invalid_role.*` and `error_body_in_character.*`, confirming the ADR-0049 checks are untouched by this extension.
5. **Full pipeline, end-to-end:** a fresh package driven through the actual completing `UPDATE ... SET generation_status = completed, generation_completed_at = now()` came back `needs_review` with `victim_mismatch.Sophie Duplock` in `structuredDefects` — confirming the trigger wiring, not just the function in isolation. With the defect still present, both `heal_completed_packages()` and `promote_complete_packages()` were run manually and correctly refused to resurrect it (status stayed `needs_review`) — confirming the recovery-path mirror ADR-0049 built extends automatically to the new classes with zero additional code. The `game_overview` was then genuinely corrected to name the right victim; `promote_complete_packages()` was re-run and correctly promoted the package to `completed` — confirming the gate doesn't block legitimate recovery once the underlying content is actually fixed.
6. **Migration history vs. live state:** the fix in step 2 was applied directly during verification (before any real package hit the buggy path), so the first-applied migration (`20260801140706_extend_completion_gate_content_detectors`) briefly differed from what was live. A second migration (`fix_extend_completion_gate_array_concat_bug`) was applied to bring migration history back in sync with the corrected live function — the same two-step-migration-equals-one-repo-file pattern already established in ADR-0047 (see its Key Files note on `20260729082237`/`20260729082931`). The single repo file `supabase/migrations/20260801_extend_completion_gate_content_detectors.sql` contains the corrected version throughout, so a fresh apply from the repo is a clean one-step operation; only this project's live DB history shows the real two-step sequence.

## Consequences

- Five new defect classes now block first completion, not just post-hoc detection. Combined with ADR-0049's structural checks, `package_completion_blocking_defects()` now covers 7 of the 8 named ADR-0042/0041/0048 detector classes (all but the deliberately-advisory `evidence_culprit_spoiler`) plus the two ADR-0049 structural invariants — everything currently known to be mechanically detectable and safe to block on.
- Some packages will newly land in `needs_review` at first-completion time instead of shipping and being caught 6 hours later by the health check (or not at all, if the defect predates health-check wiring). This is the intended trade of latency for never delivering a detectable defect, per ADR-0051.
- **`meta_text_leak`, `victim_mismatch`, `slip_culprit_leak`, and `identity_conflict` packages HOLD in `needs_review`** until a human repairs them or ADR-0051 layer 3 (child-content regenerator) ships. This is a deliberate, named gap — see Decision — not an oversight. `self_directed_question` and (indirectly, via exclusion) `missing_evidence_images` already self-heal via the ADR-0047 worker.
- No new tables, triggers, or cron jobs. The entire change is one function body; the risk surface is fully characterized by the Verification section above.
- The read-only `list_packages_with_*()` detectors and the 6-hourly health check remain as-is, now serving strictly as the post-delivery backstop for anything that predates this gate or slips past a future code path this gate doesn't cover — per ADR-0051's framing, they move further from front line to safety net.

## Discussion

The main judgment call was where to draw the exclusion line, given the task brief flagged both `evidence_culprit_spoiler` and `missing_evidence_images` explicitly for a decision rather than prescribing one. They failed the bar for different reasons, which is worth keeping distinct rather than lumping "excluded" together: `evidence_culprit_spoiler` fails on **detector precision** — the regex itself produces wrong answers often enough that blocking on it would hurt more than it helps, independent of timing. `missing_evidence_images` fails on **timing/architecture** — the detector would likely be precise (images either exist or don't), but the thing it's checking for is asynchronous by design, so "block until true" is really "block until a slower pipeline catches up," which is a UX regression dressed up as a safety gate. The task brief's own framing — "images are generated late/async, so gating at completion risks a race with normal image generation" — was the right read, and the ADR-0047 worker's existence (recall-and-self-heal, already shipped, already the same detect-not-ship-broken pattern) made this an easy call rather than a close one: the safety property this whole ADR-0051 program wants for images already exists, just implemented as a post-completion recall instead of a pre-completion block.

The second judgment call was whether to also try gating `missing_evidence_images` but only for images that are unambiguously "supposed to already exist by now" (e.g., some age threshold since generation started). Not pursued: it would reintroduce exactly the kind of judgment-call threshold-tuning ADR-0049 avoided for its own excluded structural checks, for a class that already has a working non-blocking remediation path. If evidence shows images going unremediated in practice, that's a signal to revisit the ADR-0047 worker's reliability, not to add a timing heuristic to this gate.

Worth naming plainly, echoing ADR-0049's own honesty: this migration does not make generation better. It makes the *set of defects that can reach `completed`* smaller by five classes. The underlying causes (LLM stochasticity, prompt-adherence slips) are untouched — ADR-0051 layer 3 (the child-content regenerator) is where those actually get *fixed* rather than *held*. This ADR is deliberately just the gate, same scope discipline ADR-0049 applied to its own structural slice.
