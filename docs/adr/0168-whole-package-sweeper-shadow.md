# ADR-0168: A whole-package "sweeper" pass in shadow, to replace the daily hand sweep

- **Status:** Accepted 2026-10-17 as a measurement (shadow window of 5 packages); becomes a gate or auto-apply only on the exit criterion in decision 4.
- **Date:** 2026-10-17
- **Related:** ADR-0163 (clusters, `sweep_exit_metrics`), ADR-0136 (the per-item reviewer), ADR-0165 (apply guards, image judge), ADR-0166 and ADR-0167 (the other shadow checks), ADR-0103 Addendum 56 (an LLM judge for this bug class was declined on 2026-09-26 for lack of evidence), ADR-0103 Addendum 106 (the sweep that prompted this).

## Context

Jonathan sweeps every package by hand, every day, and a handful of defects are always left that nothing caught. After 16 sweeps `sweep_exit_metrics` says: reviewer recall 52 percent (slip 54, detective 50), median 7.5 hand-found misses per package, 40 high-severity misses in total. The unowned buckets (`layer_owner = none`) are all cross-sheet facts: hidden facts known to others (C2, 26), who was where (C4, 17), who owns which item or fact (C5, 17). Six probes now run after the main review (`+p2`, `+leak`, `+fact`, `+doc`, `+pub`, requirements) and recall has not moved: each reads one item or one small candidate set against a digest.

The hand sweep works because it reads the WHOLE cast in one context and cross-checks every field. Addendum 56 (2026-09-26) declined an LLM judge for this class because the real gap then looked like sampled reading, not a missing capability, and the cost was unproven. The new evidence is the opposite: the full-cast read is exactly what costs Jonathan a daily sweep, and a package fits in one context (43k tokens for 7 sheets, 111k for 12).

## Decision

1. **Add `+sweep`, a whole-package pass** (`supabase/functions/review-package-quality/sweep-probe.ts`, `sweepProbe` in `index.ts`). One call for a cast of six or fewer, two parallel calls (halves of the cast) for a larger one. Each call sees the customer's own words, `master_context` (without `accomplicePairings`), the shared documents and every sheet, and reports only on its own half (so a sheet is not reported twice) while reading the other half as evidence. The checklist is the sweep's: facts across sheets, positions and alibis, hidden versus known, own-sheet consistency (innocent/guilty/accomplice twins), pronouns (the victim convention plus the customer's own wording), slips and leaks (template variable names, unbalanced quotes, wrong grammatical person), shared documents, the customer's brief. The reviewer's own by-design rules and ignore list are reused from `review-core.ts` so the two stay in step.
2. **It makes the creative decisions** (rule 7d, written into the prompt as rule 9): keep the reading the customer's words and the larger number of sheets support, edit the side with fewer statements, never invent a fact about another character (leave `suggested_replacement` empty and say so). Jonathan does not make creative calls.
3. **Shadow first.** Findings are stored OPEN under prompt version `+sweep` (added to `SHADOW_SUFFIXES`: never auto-applied, never in the open-findings email). A `+sweep` review row is written even with zero findings, because the unique `(package_id, prompt_version)` row is also the "already swept" marker. Spend gate: `pipeline_settings.review_sweep_probe` is a COUNT of packages still allowed (absent, 0 or anything else is off); the edge function decrements it BEFORE the paid call, so a crash can never run more packages than were approved. A cron job (`review-sweep-probe`, every 5 minutes, offset 2 minutes) calls `{"mode":"sweep_next"}`, which takes the oldest package released in the last 24 hours that has no `+sweep` row and whose second pass has finished (or that was released over 30 minutes ago), so a sheet edited by `+p2` cannot leave a stale quote in a sweep finding. A skipped package (too large, cost cap) is marked or its slot refunded so it cannot burn the budget.
4. **Exit criterion (from the vault proposal).** After the 5-package window the AI compares, per package, the `+sweep` findings with the hand sweep it does right after (`package_review_misses` rows and `human_verdict`s). If sweeper recall of the defects left for hand fixing is at least 80 percent over those packages and no edit it proposed would have been wrong, turn on auto-apply class by class behind a switch (like `review_apply_fact_findings`) with the existing apply and revert guards, and sweeping drops to sampling. Below 80 percent: rewrite the prompt on the misses (they are written into `package_review_misses` anyway) and run another window with a fresh yes; below 50 percent after two windows, drop it.
5. **Two free items shipped with it.** (a) `midQuoteItems` / `introducesMidQuote` in `review-core.ts` and a check in `autoApply`: a replacement that would close the quotation of a numbered rumor or question item in the middle is not applied (the finding stays open with a note). It would have stopped the applied `+fact` edit that left a stray quote in Larry's rumor on The Enthusiasts. A corpus scan (11,003 rumor and question fields) flags 71 items, nearly all nested single quotes; the guard blames only an edit that ADDS a flagged item, so those are harmless. (b) The image judge's subject rule now treats a wrong identity detail named on the card (which playing card, a name, a number, a colour) as "no", and its re-roll prompt for a playing card describes a full-bleed jester face and never mentions indices or suits (Flux has no negative prompt; naming them drew them).

## Is the reviewer still worth running? (Jonathan's question, 2026-10-17)

Yes for now, and the shadow window is how we decide what to drop. The reviewer is the expensive part: on The Enthusiasts it cost about 2.05 USD (main 0.82, `+p2` 0.58, probes 0.33, point-form resyncs 0.30, requirements and image judge 0.08) against 0.18 to 0.91 USD for the sweeper. It also does something the sweeper does not: it APPLIES the mechanical fixes before release (10 edits on that package, 9 good), which is why the customer never sees them. Keep the main pass for that. The candidates to retire once the sweeper has proven recall are the overlapping read-only layers: `+p2` (a second look of the same kind), then `+leak`, `+fact`, `+doc`, `+pub` (about 0.35 USD per package, 15 judged findings so far across them). The decision uses the same window: for each reviewer layer, which of its real findings the sweeper also made. A layer whose real findings are all covered goes first. The point-form resync and the image judge stay (they are repairs, not reviews).

## Calibration before the window (not counted against it beyond cost)

- **Replay on The Enthusiasts with seven known defects restored in memory** (the defects the hand sweep found, put back with `overrides`; 111k input tokens, two calls, 94 s, 0.91 USD): found 5 of 7 (the leaked `hasAccomplice` line, Riley's "their" for Lee, Larry's stray quote, Sage's "her", Cardi's secret against the rumors), missed 2 (Riley's Round 4 position against two hedged rumors, Imma's "stolen prize" in a private guilty tip). It also reported 8 more: one real new find (the reveal says the crime was "done by someone alone" and then tells the accomplice "you did not act alone"), 7 pronoun-consistency items on Imma and Lorenzo that are defensible but were decided as left in the sweep, one questionable hidden-versus-known item on an owner's own introduction, and one questionable question about Lee and Lorenzo.
- **Killer Sundae** (`4bfc800b`, detective, 7 sheets, 43k tokens, one call, 33 s, 0.18 USD): 0 findings. Its hand sweep, still to come, is the first real recall number.
- No cache breakpoint on the shared context: the two calls start together, so both would pay the cache-write price (about 0.2 USD more on a 12-sheet package).

## Alternatives considered

- **More per-item probes.** Six exist and recall is flat; they cannot see what only a whole-cast read sees.
- **Prevent upstream only (Child68, Parent88, a fact registry).** Right for C4 and C5 and already in motion, but each is gated on data that takes weeks, and none covers the long tail of slips.
- **Run the sweeper as a hard gate before release now.** No: unmeasured, and a held package is worse than a delivered one with an open finding.
- **Cache the shared context and run the halves in sequence.** Cheaper by about 0.2 USD, slower by one call (about 90 s); not worth it at this size.

## Consequences

- Every sweep now reads the `+sweep` findings (CLAUDE.md protocol, 7c) BEFORE editing and records a `human_verdict` on each; defects the sweeper missed go to `package_review_misses` as before, so recall is computable.
- Spend: about 0.2 to 0.9 USD per package for the 4 remaining packages (about 3 USD in total), plus the 0.18 and 0.91 USD already spent. Nothing runs after the count reaches 0.
- Key risk: the two halves decide "the smaller side" independently and could propose two conflicting edits. Irrelevant in shadow; auto-apply would first need a de-duplication step per conflict.

## Update 1 (2026-10-17, later): auto-apply is decided per class, not once

Jonathan asked whether the 80 percent bar is judged on the next sweep or over a number of sweeps. Answer: over the whole 5-package window (1 package swept so far, Killer Sundae, still to be swept by hand; about 2 purchases a day, so 2 to 3 days), never on one sweep. Because 5 packages carry only about 35 hand-found defects, the overall 80 percent figure is a screen, not the switch. The switch is per class, with the bar the other shadow checks use: at least 8 judged findings and 90 percent or more real, zero wrong edits, then auto-apply for that class behind its own switch with the existing guards (per-package cap, revert on a new blocking defect, customer-wording guard, the new stray-quote guard). Mechanical classes go first (template or variable leaks, stray quotes, pronoun drift, own-sheet slips). Position, hidden-versus-known and other fixes that edit a sheet other than the one the finding is about stay in shadow until the two halves' possible conflicting edits are de-duplicated and the class has its own data. Below 80 percent overall: rewrite the prompt on the misses and run another window (needs a fresh yes); below 50 percent after two windows: drop it.
